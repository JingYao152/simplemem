# MemWeaver 方案总结：创新点与流程

> 完整技术规格见 `memweaver-design.md`。本文以最短篇幅说清：MemWeaver 是什么、新在哪里、每个创新点如何运转。

## 方案一句话

MemWeaver 将 SimpleMem 的记忆库从"切窗口、抽事实、存向量"的一次性流水线，改造为**写入时持续自组织的记忆织物**：事实有生命周期、摘要是活文档、向量表示随组织结构演化——所有组织决策由 LLM 语义判断做出，全系统**没有任何需要调优的超参数**。

---

## 创新点一：写时自组织记忆织物

**问题**：固定窗口切分割裂跨 session 的话题连续性；抽取出的事实彼此孤立，旧事实过时后仍以同等地位参与检索，"上个月 Alice 还住西雅图"和"Alice 上周搬去了波士顿"在库里平起平坐。

**机制**：记忆按"线程"（跨 session 存续的话题线索）组织，写入以 session 为原子单位，分两步 LLM 决策：

```
Session 到达（边界由对话时间戳自然给出，无窗口参数）
  │
  ├─ Call A · 线程分配
  │    LLM 读取本 session 全部对话 + 现有全部线程的一行摘要，
  │    将每段对话归入已有线程或开启新线程。
  │    休眠数月的话题被重新提起时，自动接回原线程——固定窗口做不到这一点。
  │
  ├─ Call B · 抽取 + 编织（每个被触及线程一次调用，线程间并行）
  │    输入：线程当前摘要 + 线程现存全部事实 + 新分配的对话。
  │    一次调用同时产出：
  │      · 新事实（无损语句，指代与时间已消解）
  │      · 编织操作——新旧事实的关系判定：
  │          supersede  新事实取代旧事实 → 旧事实的有效期就此闭合
  │          refine     新事实细化旧事实 → 建立双向细化边
  │          bridge     跨线程实体关联   → 建立桥接边
  │      · 重写后的线程摘要（活文档，非追加）
  │
  └─ finalize · 跨线程兜底扫描
       线程分配可能把同话题的新旧事实分进不同线程，
       收尾时用本地嵌入检索跨线程近邻，交 LLM 补判漏掉的 supersede。
```

**效果**：库中每条事实携带 `[valid_from, valid_until)` 有效区间与关系边，记忆不再是事实堆，而是一张有时间轴、有结构的织物。

## 创新点二：组织与表示协同演化

**问题**：无损语句是句子级自包含的（谁、何时、何事俱全），但不携带主题级语境——"Melanie 买了水彩画笔"的向量不知道自己属于延续八个 session 的绘画爱好线索，开放域问题（"Melanie 靠什么放松？"）因此漏检。已有的上下文化嵌入（Anthropic Contextual Retrieval）是静态的：前缀一次生成、终生不变。

**机制**：条目的嵌入上下文来自它在织物中的位置，且随织物演化而更新：

```
写入时
  嵌入文本 = [所属线程摘要的一句话版] + 无损语句
  ── 前缀只参与向量计算，事实文本本身不可变（保持 SimpleMem 无损原则）

线程摘要被重写时（Call B 顺带输出）
  LLM 显式点名"哪些旧事实的表述已过时"（outdated_facts）
  → 仅被点名的条目用新摘要重新拼接、本地重算向量
  ── 语义定位取代数值漂移阈值；重嵌入是本地计算，零 API 成本
```

**效果**：表示层与组织层形成闭环——组织决定表示，写入重组组织、进而刷新表示。这是静态上下文化方法没有的更新语义。

## 创新点三：织物衍生的读取原语

**问题**：普通向量检索对"时间"和"关联"是盲的：过时事实照常命中；桥接事实因与问题直接相似度低而永远召不回。

**机制**：三个读取原语，每一个都以织物结构为前提（无有效期字段则无 ①，无编织边则无 ②③）：

```
① as-of 时点过滤
   锚点 = 记忆库最后 session 日期。
   一般问题：只检索 valid_until 为空或晚于锚点的事实——过时事实结构性出局。
   when 类问题：不过滤（问历史恰恰需要旧事实）。

② 一跳证据扩展
   对检索候选中的每个事实节点，沿三类边各走一跳：
     supersede 链（双向）→ 事实演化链成员     （时间题："之前是什么"）
     weave 边（双向）    → 跨线程桥接事实     （多跳题的缺失一环）
     归属边             → 所属线程的活体摘要  （补主题语境）
   仅一跳，入池去重，每个新条目记录 provenance（锚点 + 边类型）。

③ provenance 感知精排
   扩展后全池交叉编码器逐条打分，取 top 20 作为回答上下文。
   扩展条目的打分输入带 provenance 前缀（如 "[bridge of: <锚点句>]"）——
   否则直接相似度低的桥接事实会被精排再次淘汰，扩展白做。
   渲染时 supersede 链成员相邻排布并标注取代关系。
```

**效果**：检索从"相似度匹配"升级为"沿织物结构走证据链"，且检索基座（SimpleMem 原生三路检索）原样不动、与基线共享，增量干净归因于织物。

## 零超参数：LLM 语义决策取代数值阈值

原方案需要调优的阈值全部被替换或被数据结构消灭：

| 原本需要调的 | 现在由谁决定 |
|---|---|
| 线程归属相似度阈值 | Call A 的 LLM 分配（兜底：整 session 入新线程） |
| 摘要重写触发条件 | Call B 输出 summary_impact |
| 重嵌入触发阈值 | Call B 点名 outdated_facts |
| 编织候选检索深度 | 候选 = 同线程全量事实（结构有界） |
| 窗口大小 / 扩展截断 | session 边界 / 一跳闭包（数据结构自带） |

全系统仅存 1 个新增容量常数（精排取前 20 条，固定不调）；全部 LLM 调用 temperature=0.7。

## 与已有工作的边界

| 已有工作 | MemWeaver 的不同 |
|---|---|
| SeCom / LightMem（话题分段） | 分段是一次性的；线程跨 session 存续、可休眠可唤醒 |
| RAPTOR（层级摘要） | 树是静态一次性构建；活体摘要随写入被重写 |
| A-Mem（笔记链接） | 只链接不管生命周期；编织操作类型化且带有效期语义 |
| Zep / Graphiti（时态知识图谱） | 需要图数据库；MemWeaver 在扁平向量库上实现时点一致性 |
| Anthropic Contextual Retrieval | 前缀静态且可能污染文本；此处前缀只进向量、随摘要演化更新 |

RRF 融合、题型格式化 prompt 等 EvolveMem 已声称的读侧方法**不纳入本方案**；唯一保留的通用组件是交叉编码器重排器（标注继承，不进贡献声明）。

## 验证设计

- 同一评测框架（`test_locomo10.py`）做改动前后 A/B；所有对照系统配同一个重排器，增量只能归因于织物机制；
- 五个消融开关逐项关闭，对应论文消融表；LoCoMo 的 evidence 标注直接量化检索命中率，无需等端到端分数；
- temperature=0.7 下报 3 次运行均值±方差；每个 LLM 决策点的确定性兜底触发率入日志。

分阶段落地：P0 织物写管线与 as-of 检索（主攻时间题）→ P1 协同演化表示层（主攻单跳与开放域）→ P2 一跳扩展与精排（主攻多跳）。
